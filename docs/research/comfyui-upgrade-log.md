# ComfyUI upgrade log

## 2026-10-27: v0.43.0

Reviewed 2026-10-27 against the [v0.43.0 release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), the linked ComfyUI pull requests and first-party model pages, and the retained integration findings in [comfyui.md](comfyui.md).

### Definite release items relevant to existing concerns

- **Graph-cleanup synchronization:** v0.43.0 includes synchronization for all model-prefetch graph cleanups. The pull request says a malloc graph cleanup could destroy VRAM and that a missing sync was added; its author also says they had not reproduced the issue. This is relevant to the earlier crash/half-alive concern and the GPU-sync change already noted for 0.42.1, but does not establish that the previously observed Windows WDDM/Comfy-Aimdo crash is fixed or identify its root cause. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [PR #17178](https://github.com/Comfy-Org/ComfyUI/pull/17178), [retained finding](comfyui.md#comfyui-can-crash-and-stay-half-alive))
- **Comfy-Aimdo 0.6.0 and dynamic VRAM KV caches:** the release includes Aimdo 0.6.0 and initial dynamic-VRAM KV-cache support; the implementation applies the cache to Qwen Image 2.1 and can span VRAM and host RAM. This may be relevant to memory pressure, but the PR describes a KV-cache change rather than a fix for the earlier WDDM crash; its stated Windows test was on an RTX 3060, not this repository's RTX 4070. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [PR #17274](https://github.com/Comfy-Org/ComfyUI/pull/17274), [retained memory findings](comfyui.md#memory-and-speed))
- **MOSS-Image quality and editing controls:** the release adds RoPE scaling for higher-resolution MOSS-Image use, color/depth control, edit-LoRA support, and attention-bias/image-strength conditioning for edits; it also lists a reduction in MOSS peak memory. These changes extend the already-tested MOSS base and the previously noted experimental control route, but none is evidence of a measured benefit on the project's 4070 workflow. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [PR #17172](https://github.com/Comfy-Org/ComfyUI/pull/17172), [PR #17206](https://github.com/Comfy-Org/ComfyUI/pull/17206), [PR #17296](https://github.com/Comfy-Org/ComfyUI/pull/17296), [PR #17320](https://github.com/Comfy-Org/ComfyUI/pull/17320), [PR #17338](https://github.com/Comfy-Org/ComfyUI/pull/17338), [retained MOSS finding](../models.md#moss-image-on-comfyui-with-an-rtx-4070-2026-10-19))
- **FIBO 2.0 support and negative prompts:** native support for FIBO 2.0 Dev text-to-image and Edit Turbo image editing is included, with the PR documenting the FIBO text encoder, FLUX.2 VAE, and model-specific sampling defaults. A follow-up in the same release fixes text-to-image handling so structured negative prompts are not cleaned as ordinary text. This moves the support noted as pending in the existing research into the released ComfyUI version; it is not an app integration or quality test. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [PR #17240](https://github.com/Comfy-Org/ComfyUI/pull/17240), [PR #17285](https://github.com/Comfy-Org/ComfyUI/pull/17285), [retained FIBO note](comfyui.md#image-models-built-into-comfyui))
- **Workflow-template revisions:** v0.43.0 includes template updates through v0.11.97, so the app's copied workflows and node inputs should be checked against the installed templates when ComfyUI is updated. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [workflow-templates repository](https://github.com/Comfy-Org/workflow_templates))

### Possible candidates for later evaluation — not selected

- **FIBO 2.0 Dev and Edit Turbo:** these are plausible additions to the deferred ComfyUI edit-model evaluation: Bria describes Dev as the generation model and Edit Turbo as editing-only at four steps, while ComfyUI now has native support and Comfy-Org supplies repackaged files. The repack's weights are licensed CC BY-NC 4.0, so that restriction should be considered before use. The prior 12 GB evaluation plan and its questions remain open; this note does not recommend either model or establish fit, quality, speed, or app compatibility. ([Bria Dev model card](https://huggingface.co/briaai/Fibo-2.0-dev), [Bria Edit Turbo model card](https://huggingface.co/briaai/Fibo-2.0-edit-turbo), [Comfy-Org repack and license](https://huggingface.co/Comfy-Org/Fibo-2.0), [ComfyUI support PR](https://github.com/Comfy-Org/ComfyUI/pull/17240), [deferred evaluation](../open-threads.md#L32))
- **MOSS-Image edit/control variants:** the released color/depth adapter and edit-LoRA support make the corresponding MOSS variants possible follow-up tests alongside the already-tested base. Comfy-Org's model page identifies the adapter and edit-LoRA files and links their original model repositories; the release and support PRs establish ComfyUI support, not a result for the project's prompts or workflow. ([Comfy-Org MOSS-Image files and source links](https://huggingface.co/Comfy-Org/MOSS-Image), [color/depth support PR](https://github.com/Comfy-Org/ComfyUI/pull/17206), [edit-LoRA support PR](https://github.com/Comfy-Org/ComfyUI/pull/17296), [attention/image-strength support PR](https://github.com/Comfy-Org/ComfyUI/pull/17320), [deferred model evaluation](../open-threads.md#L8))

No models were downloaded and no inference or hardware tests were run for this review. Any follow-up benchmark should be arranged with the user ahead of time and run when the machine is otherwise idle; concurrent work can skew timing and resource measurements.
