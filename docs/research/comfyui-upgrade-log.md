### Release items relevant to the app

- **Qwen 3.x text encoders combine their parallel linears** ([#17361](https://github.com/Comfy-Org/ComfyUI/pull/17361), with a fix for a model reused without prefetching, [#17625](https://github.com/Comfy-Org/ComfyUI/pull/17625), and for fp8 Qwen generating text, [#17620](https://github.com/Comfy-Org/ComfyUI/pull/17620)). Touches the Qwen3-VL encoders behind Qwen-Image 2.1, FLUX.3 Klein and FIBO 2.0; the PR measured ~9% on a Qwen 3.5 9B generating text on a 5090. No change here: Qwen-Image 2.1, FLUX.3 Klein and FIBO 2.0 Turbo took the same time as on 0.43.2, and the same pictures each run (the bench below).
- **SeedVR2's VAE sizes its slices to free memory** ([#17508](https://github.com/Comfy-Org/ComfyUI/pull/17508)): byte-identical output when nothing is spare, otherwise caches stay on the card; 30–45% off the VAE on a 5090 for video. On the app's Upscale, one frame through the tiled VAE, no change in time for 7B or 3B, with ~0.8–0.9 GB more of the card at the peak (the bench below).
- **A guard on the audio stream's scale** in `MiniMaxH3`, the model class behind the app's H3 clips ([#17543](https://github.com/Comfy-Org/ComfyUI/pull/17543), "Fix potential crash": `getattr(…, "audio_scale", 1.0)`). Not tied to any failure seen here; an H3 clip with sound came out whole (the bench below).
- **Templates**: of the templates the app's ComfyUI image and video workflows come from, those for Qwen-Image 2.1 (and Turbo, and both edits), FLUX.3 Klein (and edit), Krea 2 int8, Anima, SeedVR2 and LTX 2.5 are byte for byte the same in `comfyui-workflow-templates-json` 0.1.132 (installed) as in 0.1.127 (from PyPI). FLUX.2 Klein, MOSS, Z-Image Turbo, Krea 2 (fp8) and MiniMax H3 i2v changed only in their model-link notes; Ming-Image's prompt rewriter, which the app leaves out, moved from `TextGenerate` to `TextGenerateV2`, and its seed from fixed to randomize. No workflow changes needed.

### The v0.43.0 release review (the Windows PC, 2026-10-27)

Reviewed 2026-10-27 against the [v0.43.0 release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), the linked ComfyUI pull requests and first-party model pages, and the retained integration findings in [comfyui.md](comfyui.md).

#### Release items relevant to existing concerns

- **Graph-cleanup synchronization:** v0.43.0 includes synchronization for all model-prefetch graph cleanups. The pull request says a malloc graph cleanup could destroy VRAM and that a missing sync was added; its author also says they had not reproduced the issue. This is relevant to the earlier crash/half-alive concern and the GPU-sync change already noted for 0.42.1, but does not establish that the previously observed Windows WDDM/Comfy-Aimdo crash is fixed or identify its root cause. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [PR #17178](https://github.com/Comfy-Org/ComfyUI/pull/17178), [retained finding](comfyui.md#comfyui-can-crash-and-stay-half-alive))
- **Comfy-Aimdo 0.6.0 and dynamic VRAM KV caches:** the release includes Aimdo 0.6.0 and initial dynamic-VRAM KV-cache support; the implementation applies the cache to Qwen Image 2.1 and can span VRAM and host RAM. This may be relevant to memory pressure, but the PR describes a KV-cache change rather than a fix for the earlier WDDM crash; its stated Windows test was on an RTX 3060, not this repository's RTX 4070. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [PR #17274](https://github.com/Comfy-Org/ComfyUI/pull/17274), [retained memory findings](comfyui.md#memory-and-speed))
- **MOSS-Image quality and editing controls:** the release adds RoPE scaling for higher-resolution MOSS-Image use, color/depth control, edit-LoRA support, and attention-bias/image-strength conditioning for edits; it also lists a reduction in MOSS peak memory. These changes extend the already-tested MOSS base and the previously noted experimental control route, but none is evidence of a measured benefit on the project's 4070 workflow. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [PR #17172](https://github.com/Comfy-Org/ComfyUI/pull/17172), [PR #17206](https://github.com/Comfy-Org/ComfyUI/pull/17206), [PR #17296](https://github.com/Comfy-Org/ComfyUI/pull/17296), [PR #17320](https://github.com/Comfy-Org/ComfyUI/pull/17320), [PR #17338](https://github.com/Comfy-Org/ComfyUI/pull/17338), [retained MOSS finding](image-models.md#moss-image-on-comfyui-with-an-rtx-4070-2026-10-19))
- **FIBO 2.0 support and negative prompts:** native support for FIBO 2.0 Dev text-to-image and Edit Turbo image editing is included, with the PR documenting the FIBO text encoder, FLUX.2 VAE, and model-specific sampling defaults. A follow-up in the same release fixes text-to-image handling so structured negative prompts are not cleaned as ordinary text. This moves the support noted as pending in the existing research into the released ComfyUI version; it is not an app integration or quality test. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [PR #17240](https://github.com/Comfy-Org/ComfyUI/pull/17240), [PR #17285](https://github.com/Comfy-Org/ComfyUI/pull/17285), [retained FIBO note](comfyui.md#image-models-built-into-comfyui))
- **Workflow-template revisions:** v0.43.0 includes templates through v0.11.97. The Windows installation's templates were compared with the app's image workflows below; no compatibility update was needed. ([release notes](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.43.0), [workflow-templates repository](https://github.com/Comfy-Org/workflow_templates))

#### Windows PC check — 2026-10-27

- The local API reports ComfyUI **0.43.0**, workflow templates **0.11.97** (matching the required version), frontend **1.57.4**, and comfy-aimdo **0.6.0**, on an **RTX 4070 with 12 GB VRAM**. It is a Comfy Desktop-managed install; its Desktop version and the previous ComfyUI version were not captured (the prior release review covered 0.42.5).
- **Model storage:** Comfy Desktop is configured to use `C:\Users\fairp\AppData\Local\Comfy-Desktop\ComfyUI-Shared\models` as its shared model directory. Put downloaded model files in the matching subfolders there (`diffusion_models`, `text_encoders`, `vae`, and so on), rather than the install's own `ComfyUI\models` directory or the Hugging Face download cache. For FIBO 2.0, installed the Dev and Edit Turbo int8 DiTs, the shared Qwen3-VL-4B int8 text encoder, and the FLUX.2 VAE as `vae/flux2-vae_fibo2.safetensors`; retained the existing shared `vae/flux2-vae.safetensors` because its contents differ. ComfyUI discovers Desktop's shared model paths through its generated `instance-model-paths` config. The weights came from [Comfy-Org/Fibo-2.0](https://huggingface.co/Comfy-Org/Fibo-2.0) and remain under CC BY-NC 4.0.
- **Workflow-template comparison:** compared all ten app image workflows with their corresponding templates installed in `comfyui-workflow-templates-json` 0.1.123, and checked their node inputs against the live `/object_info` API. No required app workflow changes were found. The templates' prompt enhancers and preview nodes remain intentionally omitted, and the app keeps its `SaveImageWebsocket` output and RGB handling. Qwen-Image 2.1's text-to-image and edit templates now include `QwenImage21Cache` set to `auto`; the app's regular Qwen workflow omits it, and the A/B above found no meaningful speed or memory benefit at 1024×1024, so it stays as-is. The edit path has not had a cache A/B. The MOSS text-to-image template still has optional skip-layer guidance off; its color/depth and edit templates are separate capabilities, not required changes to the existing text-to-image workflow, and their adapters are not installed. SeedVR2's template uses 4× resizing, while the app deliberately resizes to a chosen shorter edge; the installed API still accepts the app's dynamic `resize_type.shorter_size` input. The apparent schema warnings for these and image-reference inputs were false positives from a check that did not account for ComfyUI's dynamic inputs.
- The existing Qwen-Image 2.1 model files are available. Qwen-Image 2.1 Turbo, FLUX.2 Klein 4B, FLUX.3 Klein, Ming-Image, MOSS-Image, Z-Image Turbo, and SeedVR2 3B/7B files are also listed by the API. The `loras` and `model_patches` folders are empty, so the MOSS control/edit adapters are not installed.
- **App-path smoke:** ran one 1024×1024 Qwen-Image 2.1 render through the app's `comfyuiImageGenerator`, using a fixed seed and a public tavern still-life prompt. The app returned a valid 2.0 MB PNG, and its normal completion and cleanup path succeeded.
- **QwenImage21Cache A/B:** to check the release's dynamic-VRAM KV-cache path, ran the same 1024×1024 Qwen-Image 2.1 workflow, prompt, seed 4300 and 25 steps with `device=off` and `device=auto`, two times each, alternating modes. The cache node was added only to the in-memory test workflow; the app workflow was not changed. Each run returned a valid 1,969,631-byte PNG. End-to-end times, including the app client's normal cleanup wait, were **off: 21.68 s, 21.42 s** and **auto: 21.38 s, 21.45 s** (means 21.55 s and 21.42 s, respectively).
- **Sampled memory:** `nvidia-smi` sampled GPU memory every 250 ms; ComfyUI `/system_stats` sampled system RAM every 500 ms. The highest GPU use was **11,554 MiB off** and **11,616 MiB auto**. The highest whole-system RAM use was **11.96 GiB off** and **12.10 GiB auto**; this is system-wide memory, not ComfyUI process memory. These are sampled peaks, not guaranteed instantaneous maxima.
- On this one 1024×1024 test, `auto` was about **0.6% faster** on average, with peaks about **62 MiB more GPU memory** and **0.14 GiB more system RAM** than `off`. That is no meaningful speed or memory improvement at this size, so there is no evidence here to add the cache node to the app's default Qwen-Image 2.1 workflow. Higher resolutions and other cache modes were not tested. One preliminary cache-off render completed before a measurement-script error; its data was lost and it is excluded from the comparison above.
- The tests confirm the existing Qwen-Image 2.1 workflow runs and exercise the 0.43.0 cache node's `off` and `auto` modes. They do not assess image quality, edits, voice, upscaling, or MOSS's new adapters. The Mac has not been checked here.

No models were downloaded for the check itself; FIBO 2.0's files (above) were installed for the models that followed.
