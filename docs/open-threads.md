# Open threads

Ideas deliberately deferred, a few lines each: what it is, where it stands, and what would bring it back. Longer notes (what was tried, the options weighed) go in the research file a thread links to. Promote an item to an ADR in `docs/adr/` when we act on it.

- **Posing a Character with a ControlNet** (the owner's idea, 2026-10-09). Prompts pose people badly; a ControlNet would render a Frame to a pose, from a small 3D mannequin or a saved pose. On the Mac, mflux has ControlNets for Qwen-Image 2.1, Z-Image and Krea 2; on the PC, MOSS-Image's colour/depth control on ComfyUI. Nothing downloaded or tried. [Detail](research/people-in-pictures.md#posing-a-character-with-a-controlnet-open-thread).
- **Flaky tests under the full parallel run** (looked into 2026-10-30, the PC). The web run crashes about once in fourteen from a Deno regression since 2.9.7 ([denoland/deno#37040](https://github.com/denoland/deno/issues/37040)): rerun, and check again when Deno updates. Once in 50 runs, a jobs list wasn't a list; not reproduced. [Detail](research/windows.md#flaky-tests-under-the-full-parallel-run-open-thread).
- **Bring your own ComfyUI workflows** (the owner, 2026-11-08; context for later). A player imports a workflow of their own, names it, and picks it like a built-in Image, Video or Music Model. Open: how the app learns which input is the prompt, the seed and the size, and which node gives the output. [Detail](research/comfyui.md#bring-your-own-comfyui-workflows-open-thread).
- **Showcase page for 3D outputs** (the owner, 2026-10-26). Add an example image or link in the README so visitors can see what the 3D features produce: a SHARP scene and figures made with TripoSplat and LiTo. Prefer a small hosted interactive example if practical; otherwise use a screenshot or short capture. GitHub Pages could host static showcase files, as here.now does for the exported Compare page.
- **Reference portraits for Subject consistency** (tried 2026-10-06, Mac). A portrait of each person, made once from the Look and passed with every render, so faces don't drift between Frames. On the bench they held identity well, at 1.4–1.7× the time, and pulled the composition wider. Next: whether wording or guidance fixes the composition; FLUX.3 Klein and FIBO 2.0 Edit Turbo are other routes, untried. [Detail](research/people-in-pictures.md#reference-portraits-for-subject-consistency-open-thread).
- **Comparing edit models in Pictures** (the owner, 2026-10-29; parked for now). Each edit model's edits are a line of their own from the Original (ADR 0021), so a Frame can carry the same fix by several models. Proposed: an Edits view in the Pictures dialog, a row per Frame with edits by two or more models: first the version they were made from (the Original, whichever Image Model rendered it), then a column per edit model with its newest edit and the instruction it was told, which differs as each model is told in its own way.
- **A sprite sheet for the strip's tiles** (the owner, 2026-11-12; a future plan). The strip of Frames (`FrameStrip`) shows each Frame's full picture shrunk, and lazy loading still fetches every tile near the view: opening the 100-Frame Roleplay fresh fetched 36 pictures, about 64 MB, at 1636 px wide, and 22, about 39 MB, at phone width (the Mac, 2026-11-12). Thumbnails as a file per picture were tried and dropped, for the files they add. The owner's idea instead: one image per Session that each new picture is appended to as it's made, small, with each tile showing its part of it by cropping (CSS `background-position`), so the whole strip is one download. Open: what happens to the sheet when a picture is re-rendered, edited, deleted or the Session's Image Model is switched (rebuild it, or append and leave the old part), its size limits for a long Session (one sheet per so many Frames), and where it's made (the server, with the WebP encoder the Pictures export uses, `server/export/webp.ts`).
- **The screens on the Windows PC and a real phone** (the owner, 2026-11-13). The redesign (ADR 0039) was seen only on the Mac, at phone width in a headless browser. The owner will check it on the PC once merged to `main`, and on a phone later: touch, the on-screen keyboard over the text box (it should ride above the keyboard, the strip folding away), and dragging a Beat by touch.
- **A right-click menu on a picture** (the owner, 2026-11-13; an idea). Right-clicking a picture (in All Frames, Compare, the strip, the stage) opens a menu of what can be done with it: make it Home's thumbnail, and perhaps Re-render, Upscale, Edit, open it full size or copy its prompt. Home's star shows only on hover now, so it's easy to miss; stars shown faint on every picture were tried and dropped as cluttered. Open: what goes in it, and how a touch screen reaches it (a long press).
- **Export as a job** (the owner, 2026-11-13; context for later). The Compare export runs in its request, so closing the view loses its progress, and two at once wrote into one folder (now refused, one per Session at a time). As a job in the queue it would show its progress, carry on with the view closed and wait its turn. Open: a job kind with no model or machine, and where to say the export's folder once done.
- **An immersive view** (the owner, 2026-11-12; needs more thought). A Session's picture filling the screen, at its own address, with the latest lines over its darker side and the text box, and nothing else; a Roleplay played without Pictures shows the story on a plain dark ground. Drawn in the screens mockups (in git history: `docs/screens-mockups.html`, ADR 0039), and moved out of that work before it was built, as what it's for and how it's left want more thought: how a clip, the Frame's jobs and the strip fit, whether a Chain and a Storyboard have one, and how it's reached on a phone.
- **A folder manager and a Session export** (the owner, 2026-10-30, the Mac; context for later). A manager would list each Session folder with a short description and its kind, and count what's in it: Frames, edits, video clips, audio clips, call logs, the Image Models used. An Export that lets the player tick which of those to include, with toggles for the output's shape: not everyone wants JSON, so a Frame could come with text files of its description or dialogue, easy to copy out. Open: whether the zip is built on the server and downloaded, and how it relates to the Pictures export (`server/export/`). A changed Session folder also leaves the old Sessions behind, so the manager could move them across too. Whether an Export also plays or joins a Session's clips is to decide then (the owner, 2026-11-01): the cheap way is ffmpeg's concat by stream copy, as every clip comes out of ComfyUI's SaveVideo the same (MP4, H.264 High 8-bit 4:2:0 at ~4.4 Mb/s, AAC stereo 48 kHz), its joins cuts, as no clip lands exactly on its picture; or each clip on its own, to edit elsewhere.
  - **Start with a basic export and import** (the owner, 2026-10-30). Export zips a Session's whole folder into one zip file, written to a folder the player picks (the folder dialog from the Sessions tab). Import takes a zip, checks that it holds a `session.json`, and if so unpacks it as a folder in the current Session folder. A zip holds one Session, and a Session with work running on it isn't zipped. Still to work out: a Session id already in use (refuse, or give the import a new id), and zip slip: an entry named `../../x`, an absolute path or a symlink would write outside the Session's folder when unpacked, and a zip may come from someone else. Import checks that every entry resolves inside the Session's own folder, and refuses the whole zip if any doesn't.
