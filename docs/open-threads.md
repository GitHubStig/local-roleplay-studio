# Open threads

Ideas deliberately deferred. Promote an item to an ADR in `docs/adr/` when we act on it.

- **Persistent image sidecar.** Replace per-Turn `mflux-generate-*` CLI calls with a small Python service that keeps the Image Model loaded and exposes `POST /generate`. Trigger: model load time dominates Turn latency. Measured 2026-09-24: loading is ~5 s of a 42 s Z-Image Turbo render and FLUX.2 Klein 4B renders in ~13 s total, so the gain is small for now. Slots in behind `ImageGenerator`.
- **Edit-based rendering for Subject consistency.** Render each Turn by editing the previous image (`mflux-generate-kontext`, `mflux-generate-qwen-edit`, `mflux-generate-flux2-edit`) instead of generating from scratch. Trigger: the fixed Subject description plus a fixed seed still lets the Subject drift between Turns. Slots in behind `ImageGenerator`.
- **Starring Turns.** Let the player mark favourite Turns for a contact-sheet export. Not a new concept; a flag on a Turn.
- **Narration that contradicts the Scene.** On Declined Turns this is solved by a Scenario's `declinedNarration`. On done Turns, small Text Models still sometimes narrate something the Scene doesn't record, or record a field wrongly (spark-x2.5 4B: "take off jacket" narrated correctly but stored the jacket as "slung over one shoulder"). The image follows the Scene, so the picture and the text can disagree. Options: a larger Text Model, or a second pass that checks the narration against the Scene.
- **Idle animation between Turns.** Keep the image alive while the player is thinking: flickering candles, drifting haze, the Subject blinking or shifting her weight, with the Scene itself unchanged. Idle work must never block a Turn: it runs only after a commit, and is cancelled the moment the player sends a Direction, since it competes for the same GPU and memory. Options, cheapest first:
  1. *Browser-only effects.* A slow pan and zoom over the still, plus ambient overlays picked from Scene keywords (haze gives drifting fog, candles give a warm flicker, a rim light gives a soft pulse). Instant, and no extra rendering. Effects can't know *where* the candles are, so they stay generic.
  2. *Subject mask plus layered effects.* Cut the Subject out of the finished image with a background-removal model (mflux lists `fibo-edit-rmbg`; not downloaded yet, unverified), then animate only the background layer (fog, flicker, slight parallax) behind her. Better than rendering the background and Subject separately and compositing: separate renders don't share lighting, shadows or perspective, so the Subject looks pasted on.
  3. *Idle variant frames via image editing.* After commit, edit the Turn's image into a few near-identical frames ("eyes closed", "weight on the other foot", "candle flames taller") and crossfade or flash between them; a 150 ms eyes-closed frame every few seconds reads as a blink. Instruction-based editors in mflux 0.20: `mflux-generate-flux2-edit` (FLUX.2 Klein; weights already cached, likely ~15 s per frame), `mflux-generate-qwen-edit` (Qwen Image Edit, ~20B, not downloaded, much slower), `mflux-generate-kontext`, and `mflux-generate-fibo-edit`, which takes a `--mask-path` to edit only the background. The engine, not the player, writes these edit instructions, from a fixed list, so they stay within the Shoot Brief.
  4. *True image-to-video* (a 2–4 s loop from the still). mflux has no video models; this needs a separate local runtime and likely takes minutes per clip on a Mac. Out of reach for now.
- **Filter the Scene text.** The `imagePrefix` asserts what must be true in every image, but nothing removes unwanted words from the Scene itself. A Text Model that ignored the System prompt could write them into an accepted Turn's Scene, and they would reach the image prompt (see [ADR 0002](adr/0002-guardrails-enforced-by-the-engine.md)). Options: a term list checked before rendering (fail or retry the Turn), or a second Text Model pass that checks the Scene against the Setup.
- **Configurable image transitions.** Turn images currently crossfade over 700 ms (on purpose, even when the system asks for reduced motion). Add a Settings option for the transition style (crossfade, fade through black, slide, a slow zoom in, a "flash" like a camera shutter, none) and its duration. It's a display preference, so it belongs per browser like the theme, not in `settings.json`.
  - *While rendering* is a separate choice from the swap itself, so a toggle of its own: leave the current image as is; **blur and dim it** (about 6–8 px plus slight darkening) until the new image is ready, then sharpen into it; or **show the image forming**, using mflux's `--stepwise-image-output-dir` (flagged experimental; decodes every step, so it adds render time; unmeasured) to stream each denoising step, so the picture visibly resolves from noise. On Cancel or failure the current image must return to sharp.
- **Forking from an older Turn.** Picking a Turn in the Turn Log only changes what's shown (a "Viewing Turn 1 of 4 · Back to latest" pill says so); the next Direction always continues from the latest Turn. To explore "what if" from an earlier Turn:
  1. *Continue from this Turn* (medium): a button on an older Turn starts a new Session with Turns 0 to N copied (same Scenario, seed and settings) and carries on there. The original Session is untouched, and each Session stays a simple line, so the Turn engine and ADRs 0001/0003 don't change. Copies need fresh image file names.
  2. *Branches inside one Session* (large): the Turn Log becomes a tree. Changes the data model, the Turn Log UI and storage; only worth it if branching becomes central to play.
