# Open threads

Ideas deliberately deferred, a few lines each: what it is, where it stands, and what would bring it back. Longer notes (what was tried, the options weighed) go in the research file a thread links to. Promote an item to an ADR in `docs/adr/` when we act on it.

## The app

What the app does or could do: features, models it offers, how it's installed and shown.

- **Bring your own ComfyUI workflows** (the owner, 2026-11-08; context for later). A player imports a workflow of their own, names it, and picks it like a built-in Image, Video or Music Model. Open: how the app learns which input is the prompt, the seed and the size, and which node gives the output. [Detail](research/comfyui.md#bring-your-own-comfyui-workflows-open-thread).
- **Reference portraits for Subject consistency** (tried 2026-10-06, Mac; a day of trials 2026-11-22, both machines). A portrait of each person, made once from the Look, so faces don't drift between Frames. Passed into the render, they hold faces but pull expression, pose and unnamed clothes towards the portrait. Rendering without them, then repainting only the faces with the portraits as an edit, keeps the moment: on both machines, every face in one edit, the heads found by the Qwen3-VL Qwen-Image 2.1 already loads, about 2.6× a plain render. Next, if built: the seam where a hard-edged box ends (soften it or give it room), edits passing a second image, and the portraits seeded apart from the Frames. A barrier: only some Image Models take reference images. [Detail](research/people-in-pictures.md#reference-portraits-for-subject-consistency-open-thread), [pictures](bench/reference-portraits/2026-11-22/README.md).
- **A sprite sheet for the strip's tiles** (the owner, 2026-11-12; a future plan). The strip of Frames (`FrameStrip`) shows each Frame's full picture shrunk, and lazy loading still fetches every tile near the view: opening the 100-Frame Roleplay fresh fetched 36 pictures, about 64 MB, at 1636 px wide, and 22, about 39 MB, at phone width (the Mac, 2026-11-12). Thumbnails as a file per picture were tried and dropped, for the files they add. The owner's idea instead: one image per Session that each new picture is appended to as it's made, small, with each tile showing its part of it by cropping (CSS `background-position`), so the whole strip is one download. Open: what happens to the sheet when a picture is re-rendered, edited, deleted or the Session's Image Model is switched (rebuild it, or append and leave the old part), its size limits for a long Session (one sheet per so many Frames), and where it's made (the server, with the WebP encoder the Pictures export uses, `server/export/webp.ts`).
- **The screens on a real phone** (the owner, 2026-11-13). The redesign (ADR 0039) has been seen at phone width only in a headless browser; checked on the Windows PC since (2026-11-17). The owner will check it on a phone: touch, the on-screen keyboard over the text box (it should ride above the keyboard, the strip folding away), dragging a Beat by touch, and a long press on a picture opening its menu (not a tap, nor Safari's own image menu; 2026-11-17, checked in tests only).
- **An immersive view** (the owner, 2026-11-12; needs more thought). A Session's picture filling the screen, at its own address, with the latest lines over its darker side and the text box, and nothing else; a Roleplay played without Pictures shows the story on a plain dark ground. Drawn in the screens mockups (in git history: `docs/screens-mockups.html`, ADR 0039), and moved out of that work before it was built, as what it's for and how it's left want more thought: how a clip, the Frame's jobs and the strip fit, whether a Chain and a Storyboard have one, and how it's reached on a phone.
- **Markdown per Frame in a Session export** (the owner, 2026-11-24; kept for later, as no one has asked for it). A Frame's lines, who speaks and its Image Prompt in a Markdown file beside its pictures and clips in the zip, so they can be used in a video editor without reading JSON. The export is built ([design/session-manager.md](design/session-manager.md), ADR 0043).
- **Installing the app** (the owner, 2026-11-18). The app has no version number yet: a release workflow needs one, for updates and to show which version is running. Parked: signing (no paid Apple Developer ID, so a Mac download meets Gatekeeper's warning), a release workflow and updates (`Deno.autoUpdate()` doesn't apply updates on Windows yet), and the bet on Deno itself, whose future the owner is unsure of. [Detail](research/installing.md).
- **A first-run setup page** (the owner, 2026-11-21; an idea for the installed app). The first time an installed app starts, a page shows what this machine has and what's missing, from what `server/features.ts` works out at startup: each tool (uv, mflux, mlx-audio, ComfyUI and its nodes, Ollama or another Text backend), what it's for, which features it would turn on (voices, 3D, style scores, pictures), and how to install it, with links. A Skip button closes it for good, and Settings could open it again. It could install some things too: when uv is missing, download Astral's standalone uv (one file, about 20 MB) into the app's data folder and use it, so no player has to install uv, with or without their own Python. A plain Python instead of uv isn't worth it: the tools need exact Python versions (3.14, LiTo 3.13), separate environments, PyTorch's CUDA index on a PC and the locks beside each script, all of which uv does. The hf CLI isn't needed: mflux and the Python tools download their own models, and the CLI is only for clearing the cache by hand ([hf-cache.md](hf-cache.md)).
- **Bringing a Roleplay's Look up to date with the story** (parked 2026-10-19). The Look is one timeless description, so after a time skip pictures keep the old looks unless it's edited by hand, which changes early Frames too. Parked as too much work for a rare event; Look versions anchored to Frames would get it right. Revisit if time skips or lasting changes become common in play. [Detail](research/people-in-pictures.md#bringing-a-roleplays-look-up-to-date-with-the-story-parked).
- **Long Roleplays.** Every call sends the whole conversation. Once a Roleplay nears the Text Model's context (131,072 tokens for gemma4 here), summarise the oldest exchanges into the system message, or drop them. Not needed yet.
- **A game made of rooms, and what a Roleplay can't do** (the owner, 2026-11-22; a brain dump, nothing concrete). A Roleplay has no goal or end to reach, sends the whole conversation with every Reply, keeps the scene's state only in that conversation (ADR 0007), and is one-on-one. The owner's picture of something else: a game of several rooms or stages, each with something the player must work out to go on; the story carries forward only each room's summary and result, not its conversation; and what the Text Model needs to keep straight (the player's inventory, achievements, looks and so on) is kept as data by the app, not left in the conversation. If it's built, it's a new kind of Session with its own idea, sharing what it can with a Roleplay, not a second copy of it; features such as reference portraits and an earlier Look go into the Roleplay as it is (2026-11-22).
- **Music** (2026-11-22). Music in a Roleplay is built ([design/music.md](design/music.md)); this is what's left of it. [Detail](research/music-in-play.md).
  - **How well it fits the story.** A whole story was "sort of passable" (2026-11-09); the Score's instruments, awe, the `uneasy` shape, how strongly danger comes in, a steer's limits and a choir under a spoken line are each still open. Where to start: play a whole story through and list where the music fits worst, then rework the Score's prompt, which every Cue is built from. [Detail](research/music-in-play.md#what-still-fits-badly).
  - **End credits song** (2026-11-06; fun, not high on the list). A button plays a song about the story's ending, its lyrics by the Text Model. [Detail](research/music-in-play.md#end-credits-song).
  - **Music for Storyboards** (2026-11-09). A Storyboard has a set start and end, more like a 30-second ad or a music video, so a short one may want one continuous piece rather than Cues. [Detail](research/music-in-play.md#music-for-storyboards).
  - **Stingers: undecided.** Score the Roleplay can mark one on a Frame, and the Music tab shows it as text, but nothing sounds. Whether ACE-Step can make a short, exact hit hasn't been tried; if not, take them out of the prompt and the data.
  - **Other music models** (2026-11-09). When a new one comes out: a newer MiniMax Music, YuE 2 and HeartMuLa, against ACE-Step 1.5 on the bench ([bench/music-models/](bench/music-models/README.md)), judged by ear. None looked up yet; YuE and HeartMuLa were thought slow, untested. A newer MiniMax must fix what dropped Music 3: its length is its own, and voices come in where none were asked. Each model keeps its own adapter and caption style, as each one's prompt format mattered a great deal.

## Development and upkeep

The codebase, its tools and the runtimes it stands on, nothing a player would see. Most wait on an upstream release, so check them when one lands.

- **Flaky tests under the full parallel run** (looked into 2026-10-30, the PC). The web run crashes about once in fourteen from a Deno regression since 2.9.7 ([denoland/deno#37040](https://github.com/denoland/deno/issues/37040)): rerun, and check again when Deno updates. Once in 50 runs, a jobs list wasn't a list; not reproduced. [Detail](research/windows.md#flaky-tests-under-the-full-parallel-run-open-thread).
- **TTS Audio Suite from the registry again, and closing #366** (checked 2026-11-01). Comfy's registry still approves only 5.8.4, which has the worker bug, so the PC runs the nightly. Trigger: a release from 5.9.3 on approved; then switch the PC back, check a voice design works, and comment on #366. [Detail](research/comfyui.md#tts-audio-suite-from-the-registry-again-open-thread).
- **Qwen-Image 2.1 Turbo's text encoder stored twice** (2026-10-17, Mac). Turbo's repo holds the base model's text encoder, so the Hugging Face cache keeps 17.5 GB twice; the owner chose to keep both for now. Check with each mflux release whether Turbo loads it from the base repo. [Detail](research/image-models.md#qwen-image-21-turbos-text-encoder-stored-twice-open-thread).
- **MOSS-Image on mflux** (2026-10-27, Mac). mflux 0.24.0 renders black from prompts over ~200 tokens (mflux #920, fixed on main), so it waits for 0.24.1; then settle its steps and guidance against ComfyUI's, and try Quantize and the step-distilled LoRAs. [Detail](research/image-models.md#moss-image-on-mflux-open-thread).
- **TypeScript 7 for the web app** (parked 2026-10-21). vue-tsc can't run on TypeScript 7. Trigger: TypeScript 7.1 final and a released Vue Language Tools v4; then move the web's check to `tsc` with the content mapper and drop vue-tsc. [Detail](research/typescript-7.md).
